Online Payments (Razorpay)

When off, the "Pay Now" button on every package and the booking flow is replaced with a "Call to Book" CTA. Existing bookings are unaffected.

Leave blank to use the default message.

Booking Advance — Flat per-head (no longer a percentage)

The booking advance charged via Razorpay is now a flat amount per traveller — not a percentage of the trip cost. The values are hard-coded in js/checkout.js in the ADVANCE_BY_PKG map:

  • Budget & Standard packages: ₹6,000 per traveller
  • Luxury, Premium & Honeymoon packages: ₹11,000 per traveller

To run a per-customer discount instead, open the Customers tab and click the Discount button on the customer's row — that discount auto-applies on top of any coupon code at checkout.

The legacy global “advance percentage” setting below is kept for reference only — changing it has no effect on what customers actually pay.

Razorpay Mode — LIVE

Toggle ON to switch the public checkout to Razorpay's Test Mode — ideal for end-to-end QA of booking, cancellation and auto-refund without spending a single rupee. Toggle OFF to revert to LIVE keys (real money). The change applies the moment Settings are saved — no redeploy needed.

⚠️ Don't forget to also swap the refund Worker secrets when you flip this toggle — otherwise refunds will fail with id does not exist because LIVE secrets can't refund TEST payments and vice-versa. See razorpay_test_mode_guide.md → Step 3.

Get this from Razorpay Dashboard → Test Mode → API Keys. Must start with rzp_test_. The key SECRET is never stored here — it's set as a Cloudflare Worker secret via wrangler secret put.

Developer Console Lock

When on, normal visitors cannot open DevTools (F12, Ctrl+Shift+I), right-click for "View Source", or save the page. Admins are always exempt — you keep full DevTools access whenever you're logged in. Toggle off to allow everyone to use the console (useful when debugging on the live site).

Push-Notification Ads — CHECKING…

Site-wide kill switch for the third-party push-notification ad network (zone 11069054 via /sw.js). Toggle OFF to immediately stop registering the service worker on new visits AND unregister it on returning visitors' next page-load. Useful when:

  • Your AdSense application is under review (push-ads will get it rejected).
  • Ezoic flags a ToS violation about competing ad networks.
  • You see a spike in bounce rate / push-permission complaints.

Admins & staff are always exempt — you never see push prompts even when this toggle is ON. Booking / checkout / dashboard pages are also ad-free by design (the script never loads there).

Forward chats to WhatsApp

When enabled, every customer message lands in your WhatsApp via Meta's WhatsApp Cloud API. Reply back from WhatsApp and your message returns to the customer's chat in real-time. Setup: see whatsapp_setup.md in the repo.

The Meta Access Token + App Secret are not stored here — they live as Cloudflare Worker secrets on the bridge worker. See whatsapp_setup.md.

Forward chats to Telegram

When enabled, every customer message also lands in your Telegram via the telegram-bridge Cloudflare Worker. Reply in your bot chat and the message returns to the customer's open browser within ~1 second — same flow as WhatsApp, but with a free bot you create in @BotFather. Setup: see telegram_setup.md in the repo.

The bot token + webhook secret are not stored here — they live as Cloudflare Worker secrets on the telegram-bridge worker. See telegram_setup.md.
Quick test: open your bot in Telegram and send /start.
